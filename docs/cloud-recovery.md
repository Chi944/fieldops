# Recover a hosted workspace locally

The operator can make a read-only backup of one settled hosted workspace and restore it into a **new** local directory. This does not change or delete cloud data, restore a cloud database, transfer accounts, or call an AI model. The backup contains private originals and quotation text; it is not encrypted. Keep the ignored output in private storage.

Use Node.js 24 with this repository's installed dependencies. First finish or cancel every processing job, including jobs waiting for model quota, and finish or remove incomplete uploads. Avoid edits until the copy finishes. The command refuses active work and a changed source snapshot instead of publishing a mixed backup.

For an incident or planned recovery, set **`FIELDOPS_UPLOADS_ENABLED=false`** in the production web environment and redeploy/restart that runtime. An authenticated `/api/status` response must then report `canUpload:false` and the temporary-pause reason. This blocks pasted uploads, new/resumed upload tickets, upload finalization and processing retries on the server. It preserves saved comparison reads, source downloads, corrections, exports and deletion. Local personal workspaces ignore this cloud pause. Restore `true` (the default when unset) and redeploy/restart to resume admission.

The switch does not cancel already admitted jobs, stop an in-flight request, revoke an issued five-minute storage PUT ticket, or freeze manual edits. Finish or cancel jobs and stop edits before the backup; delete unfinished upload intents if they cannot be completed. If processing itself must stop, separately cancel the affected runs and pause the worker through its existing operator controls. A pause is admission control, not a storage shutdown: private originals remain available and retained according to normal deletion rules.

The explicit environment file must contain `FIELDOPS_DATABASE_URL` for the restricted runtime login and `NEON_STORAGE_ENDPOINT`, `NEON_STORAGE_ACCESS_KEY_ID`, `NEON_STORAGE_SECRET_ACCESS_KEY`, `NEON_STORAGE_REGION`, and optionally `NEON_STORAGE_BUCKET` (default `quotations`). It never falls back to the administrative `DATABASE_URL` or inherited storage credentials. Both the environment file and destination must be Git-ignored paths inside this FieldOps repository; symbolic-link paths and existing destinations are refused. Do not put credentials in command arguments.

`--owner` is the workspace owner's managed Auth **UUID**, as returned by their authenticated `/api/status` user ID. It is not their numeric GitHub account ID. This is an operator tool using private server credentials, not an endpoint exposed to other buyers.

```powershell
npx tsx scripts/cloud-backup.ts --owner=AUTH-USER-UUID --env-file=.env.fieldops.production.local --to=.fieldops/backups/hosted-NEW-NAME
npm run personal:restore -- --input=.fieldops/backups/hosted-NEW-NAME --verify
npm run personal:restore -- --input=.fieldops/backups/hosted-NEW-NAME --destination=.fieldops/personal-recovered-NEW-NAME
npm run personal -- --data=.fieldops/personal-recovered-NEW-NAME
```

Replace `AUTH-USER-UUID` and both fresh directory names before running. `.env.fieldops.production.local` is this installation's active production configuration; do not use the historical `.env.cloud.local` file from the superseded project. An unknown owner with no workspace is rejected; an existing empty workspace produces a clearly reported zero-comparison backup. The normal launcher keeps restored processing manual by default; enabling local AI remains a separate explicit option. Existing personal data and running servers are untouched. The launcher chooses loopback ports 3001–3009 and never stops another process.

The backup reads current comparisons, documents, terminal jobs, extraction versions, parsed evidence, validated checkpoints and comparison history in one owner-scoped PostgreSQL statement. Every original is fetched sequentially through the existing bounded private-storage reader and checked against its saved SHA-256 and byte count. A second capture must match the first after all downloads. Each database read has the runtime timeout and each object read the storage timeout; the complete command's duration grows with the number and size of originals. A captured JSON state larger than 128 MiB is refused.

Recovery preserves comparison revisions, quotation/document/source IDs, original interpretations, corrections and correction authors. Current records are rebound to `local-user` / `local-workspace` and local object paths; hosted task handles are removed. Prior cloud comparison versions are retained in `state.json` under `cloudRecoveryArchive` for inspection, but the local interface does not expose a history browser. Deleting a restored source removes all archived versions of its comparison from active local state; deleting the comparison does the same. The separate original backup remains unchanged until you remove it. The copy does not include Auth rows, credentials, invitation records, provider billing reservations, deletion tombstones, already deleted documents or other owners' workspaces.

An error retains `.fieldops-incomplete`; normal verification and restore reject that directory. Keep it private, investigate the fixed error, and retry into another fresh destination. Never remove the marker to bypass verification. SHA-256 detects accidental corruption, not a malicious person who can rewrite the files and manifest. App deletion cannot recall this backup; delete unneeded backup directories according to your own retention policy.

Automated verification uses synthetic in-memory transport, the actual PostgreSQL migrations under the restricted runtime role, and a real local restore. It checks ownership, current corrections, evidence/history preservation, unchanged-source detection, corrupt/missing originals, unfinished work and refusal to overwrite.

On 2026-09-20, an authorized hosted synthetic recovery drill completed at 11:24 UTC. A preliminary owner-scoped SQL check proved that the selected workspace contained exactly the one authorized comparison and five uploaded, settled synthetic documents. The same scope was rechecked on both immutable captures. The backup and new-directory restore verified **5 original files / 538,486 bytes**, preserved **197 source spans** across five quotations (27, 58, 40, 33 and 39), rebound the local owner and object paths, and left **zero pending local jobs**. It made no model calls, cloud mutations or server launches. The ignored `.fieldops/cloud-recovery-drill-receipt.json` records local recovery locations and non-content verification metadata. This establishes recovery for that synthetic fixture set; it does not establish cloud restoration, encrypted backups or recovery of every possible document format.
