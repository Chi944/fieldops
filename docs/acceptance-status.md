# First-release acceptance status

This record separates implementation from evidence. [FieldOps](https://fieldops-eight-blue.vercel.app) has a working hosted parser/manual-review workflow backed by the dedicated Neon database, managed GitHub Auth, private object storage and production Trigger worker. Its source is in the [new FieldOps repository](https://github.com/Chi944/fieldops). On 20 September, five hosted file formats produced 197 source spans, and a scoped backup restored all five originals and their evidence locally. The hosted deployment remains **parser-only**, with no production Groq key. Earlier tiny local AI examples succeeded, but the latest development investigation accepted no complete benchmark quotation and made no held-out requests. Current release and deployment evidence is in [release verification](release-verification.md); the measured AI limitations are in the [20 September reliability report](ai-reliability-2026-09-20.md). Earlier records retain their original scope.

## Personal-use update

The personal launcher isolates data in `.fieldops/personal`, forces cloud access off and defaults to parser-only processing; explicit `--ai` validates the private Free/ZDR model settings, selects an available loopback port outside 3000, and confirms actual API capabilities before reporting ready. Local manual review, matching and both exports passed the recorded production-build browser workflow. A separate local AI workspace on port 3003 now completed two tiny synthetic extractions, AI matching, buyer approval, a correction retaining its original value/discrepancy, and Excel export. This is a working small example, not benchmark accuracy. Backup and restore commands preserve original hashes, source evidence and correction history, refuse live sessions/existing destinations and use synthetic round-trip tests. See [personal use](personal-use.md) and [release verification](release-verification.md).

## Measured evidence and remaining gates

The published [evaluation report](evaluation-report.md) identifies the exact dataset and configuration hashes for its offline run. It measures parser identifier presence, source locator presence and bounds, baseline matching and parser latency. These denominators must not be renamed field extraction accuracy, AI line detection, semantic source correctness or production reliability. The [independent gold review](../eval/gold-review.md) records its subset and the raw-evidence metadata defects that were corrected.

The historical 13 September hosted slice used commit `6dab810`, Vercel **READY** deployment `dpl_5Ly8SyyW7tWVYR2GaNk84wKqR1Qo`, and passing [Linux CI run 34722616140](https://github.com/Chi944/fieldops/actions/runs/34722616140). Hosted synthetic comparison `cac81546-de10-4db7-9e79-2aac9986a2ed` received two pasted originals processed by production Trigger runs `run_06g9fesgnamc9jnomqim3bnm01` and `run_06g9ff0ulcomfltlr5vqqs7101`. The public demonstration, **hosted pasted-text/manual comparison slice and five-file hosted parser sample passed for their recorded runs**. Private-cloud acceptance still needs uninvited and two-real-account cross-access checks, forced interrupted processing/cancel/retry and quota recovery. Tests with substituted authentication and independent owner rows do not replace two real hosted accounts. See [hosted acceptance](hosted-acceptance.md) for precise evidence and cleanup boundaries.

Evaluation configuration hashes include `package.json`, `package-lock.json`, Node version/platform/architecture, and the actual English OCR language-asset SHA-256 (or an explicit missing marker). Parser/dependency/runtime upgrades therefore cannot silently reuse earlier request checkpoints or run IDs. New reports record that runtime and asset identity; older reports retain their original measurement metadata.

Live AI credentials are configured only for the explicitly enabled local path. The [20 September reliability report](ai-reliability-2026-09-20.md) records eight provider responses, zero accepted complete benchmark quotations and zero held-out requests; usage is missing for four responses. Intermediate chunk acceptance is not complete-document success, and this adaptive investigation is not an accuracy estimate. Full AI release still requires successful multiformat development evaluation, a frozen configuration, then the untouched held-out split with actual field, row, matching, ambiguity, source, latency and usage denominators. The earlier two tiny local successes do not establish those results. Hosted AI remains blocked while the parser/manual workflow is usable.

## Deferred beyond this release

DOCX, legacy XLS, handwriting and broad multilingual OCR; arbitrary merged/nested tables and reconstructed spreadsheet formulas; graduated discounts/tiers; automatic quote-level discount/tax allocation; mixed bundle allocation and milestone scheduling; automatic supplier-specific rounding policies; live FX; semantic scoring of arbitrary buyer requirements; weighted ranking; shared team administration; ERP/email integrations; automatic age-based purge of completed originals/history; and production-scale monitoring are follow-up work. Unsupported input must retain its original and explain the recovery path.
