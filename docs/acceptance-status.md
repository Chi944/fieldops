# First-release acceptance status

This record separates implementation from evidence. [FieldOps](https://fieldops-eight-blue.vercel.app) now has a working hosted parser/manual-review workflow backed by the dedicated Neon database, managed GitHub Auth, private object storage and production Trigger worker. Its source is in the [new FieldOps repository](https://github.com/Chi944/fieldops). The hosted deployment remains **parser-only**, with no production Groq key. A separately enabled local AI workspace has completed two tiny synthetic extractions and an AI-proposed match; the full AI benchmark remains incomplete. Current evidence is in [release verification](release-verification.md). Earlier setup and test records retain their original scope.

## Personal-use update

The personal launcher isolates data in `.fieldops/personal`, forces cloud access off and defaults to parser-only processing; explicit `--ai` validates the private Free/ZDR model settings, selects an available loopback port outside 3000, and confirms actual API capabilities before reporting ready. Local manual review, matching and both exports passed the recorded production-build browser workflow. A separate local AI workspace on port 3003 now completed two tiny synthetic extractions, AI matching, buyer approval, a correction retaining its original value/discrepancy, and Excel export. This is a working small example, not benchmark accuracy. Backup and restore commands preserve original hashes, source evidence and correction history, refuse live sessions/existing destinations and use synthetic round-trip tests. See [personal use](personal-use.md) and [release verification](release-verification.md).

## Measured evidence and remaining gates

The published [evaluation report](evaluation-report.md) identifies the exact dataset and configuration hashes for its offline run. It measures parser identifier presence, source locator presence and bounds, baseline matching and parser latency. These denominators must not be renamed field extraction accuracy, AI line detection, semantic source correctness or production reliability. The [independent gold review](../eval/gold-review.md) records its subset and the raw-evidence metadata defects that were corrected.

Current release evidence is commit `6dab810`, Vercel **READY** deployment `dpl_5Ly8SyyW7tWVYR2GaNk84wKqR1Qo`, and passing [Linux CI run 34722616140](https://github.com/Chi944/fieldops/actions/runs/34722616140). Hosted synthetic comparison `cac81546-de10-4db7-9e79-2aac9986a2ed` received two pasted originals processed by production Trigger runs `run_06g9fesgnamc9jnomqim3bnm01` and `run_06g9ff0ulcomfltlr5vqqs7101`. Actual browser work then completed source-linked manual entry, explicit source-coverage review, baseline matching/approval, comparison and workbook download/reopen at revision 12. No AI extraction occurred in this hosted scenario.

An earlier integrated release run passed **95 unit/integration tests across nine files**, **6/6 local browser tests in 43.6 seconds**, and **4/4 public production browser tests in 22.2 seconds**, with [Linux CI at commit 165415c](https://github.com/Chi944/fieldops/actions/runs/34712631590). Those counts describe that historical run, not the current suite. CI, fixture and injected-response results are separate from AI accuracy.

The public browser suite covers the fictional quotation workflow, matching edits, correction history, a downloaded workbook, print rendering, automated accessibility checks and mobile keyboard/dialog use. The local suite additionally verifies actual source parsing and manual recovery with AI disabled. Automated axe checks on the tested views found no violations under the selected WCAG A/AA tags; this is not full accessibility certification or coverage of every browser. The hosted private workspace now supports authenticated persistence and parser-only uploads. Hosted AI remains disabled with no production Groq key.

The public demonstration gate and **hosted pasted-text/manual comparison slice are passed for the recorded runs**. Reload, logout, restored access after sign-in and deletion also passed. Private-cloud acceptance still needs uninvited and two-user cross-access checks, the hosted real-file format matrix, forced interrupted processing/cancel/retry, quota recovery and mixed-file failure. See [hosted acceptance](hosted-acceptance.md) for precise evidence and cleanup boundaries.

Evaluation configuration hashes include `package.json`, `package-lock.json`, Node version/platform/architecture, and the actual English OCR language-asset SHA-256 (or an explicit missing marker). Parser/dependency/runtime upgrades therefore cannot silently reuse earlier request checkpoints or run IDs. New reports record that runtime and asset identity; older reports retain their original measurement metadata.

Live AI credentials are configured only for the explicitly enabled local path. Full AI release still requires successful multiformat development evaluation, a frozen prompt/parser/rule configuration, then a run of the untouched held-out split with actual field, row, matching, ambiguity, source, latency and usage denominators. Two small successful quotations do not establish those results; observed structured-output failures remain a limitation. The current application provides the labeled demonstration, working hosted and local parser/manual workflows, and a small verified local AI workflow under continuing evaluation.

## Deferred beyond this release

DOCX, legacy XLS, handwriting and broad multilingual OCR; arbitrary merged/nested tables and reconstructed spreadsheet formulas; graduated discounts/tiers; automatic quote-level discount/tax allocation; mixed bundle allocation and milestone scheduling; automatic supplier-specific rounding policies; live FX; semantic scoring of arbitrary buyer requirements; weighted ranking; shared team administration; ERP/email integrations; automatic retention cleanup; and production-scale monitoring are follow-up work. Unsupported input must retain its original and explain the recovery path.
