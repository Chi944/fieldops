## Measured evidence and remaining gates

The published [evaluation report](evaluation-report.md) identifies the exact dataset and configuration hashes for its offline run. It measures parser identifier presence, source locator presence and bounds, baseline matching and parser latency. These denominators must not be renamed field extraction accuracy, AI line detection, semantic source correctness or production reliability. The [independent gold review](../eval/gold-review.md) records its subset and the raw-evidence metadata defects that were corrected.

The integrated release run passed **95 unit/integration tests across nine files**, **6/6 local browser tests in 43.6 seconds**, and **4/4 public production browser tests in 23.9 seconds**. The Next.js production build and Vercel deployment passed. [GitHub Linux CI](https://github.com/Chi944/fieldops/actions/runs/34711908349) is green at commit `3d97e58`. These are execution results, separate from the versioned parser evaluation; they do not turn fixture or injected-response assertions into AI accuracy.

The public browser suite covers the fictional quotation workflow, matching edits, correction history, a downloaded workbook, print rendering, automated accessibility checks and mobile keyboard/dialog use. The local suite additionally verifies actual source parsing and manual recovery with AI disabled. Automated axe checks on the tested views found no violations under the selected WCAG A/AA tags; this is not full accessibility certification or coverage of every browser. The public deployment's actual `/api/status` reports `canUpload: false`, `canPersist: false` and `canExtract: false`; no Vercel environment variables are configured, and the deployment uses the verified Hobby plan.

The public demonstration gate is **passed for the recorded release run**. Private-cloud release still needs invited and uninvited OAuth tests, cross-user source access checks, a real synthetic upload/worker/cancel/retry cycle, quota recovery and deletion on hosted Supabase and Trigger. Those services remain unconfigured. Post-update local checks pass; [release verification](release-verification.md) records the final deployment and CI checks. Evaluation configuration hashes now include `package.json`, `package-lock.json`, Node version/platform/architecture, and the actual English OCR language-asset SHA-256 (or an explicit missing marker). Parser/dependency/runtime upgrades therefore cannot silently reuse earlier request checkpoints or run IDs. New reports record that runtime and asset identity; older reports retain their original measurement metadata.

Live AI release requires the user's configured credentials, successful development evaluation, a frozen prompt/parser/rule configuration, then a held-out run with actual field, row, matching, ambiguity, source, latency and usage denominators. Missing credentials are a precise verification blocker, not permission to use another provider or invent results. The current application is a labeled demonstration plus a real local parsing/manual-review workflow with an implemented, disabled AI adapter.

## Deferred beyond this release

DOCX, legacy XLS, handwriting and broad multilingual OCR; arbitrary merged/nested tables and reconstructed spreadsheet formulas; graduated discounts/tiers; automatic quote-level discount/tax allocation; mixed bundle allocation and milestone scheduling; automatic supplier-specific rounding policies; live FX; semantic scoring of arbitrary buyer requirements; weighted ranking; shared team administration; ERP/email integrations; automatic retention cleanup; and production-scale monitoring are follow-up work. Unsupported input must retain its original and explain the recovery path.
