## Initial diagnosis

The previous contract permits arbitrary strings in fields that application code requires to be precise decimals, and asks the model to regenerate literal excerpts already owned by parsers. Previous rejections include unit text inside minimum-order numeric values, invented column labels in excerpts and malformed provider JSON. A separate in-memory regression also found that item identifiers/descriptions alone could satisfy row coverage while explicit quantities/prices remained unextracted. These are distinct failures: improving response acceptance must not weaken completeness or evidence checks.

Current [Groq documentation](https://console.groq.com/docs/structured-outputs) describes strict structured output with required properties, closed objects and union types. Schema conformance does not establish correct interpretation; application source and calculation checks remain necessary. No provider feature or stronger reliability claim is inferred from that documentation.

## First candidate: request-schema compatibility failure

The typed adapter now distinguishes numeric and text fields by section, retains item-specific attributes at item scope, and keeps narrow model-provided excerpts. Charge attributes currently retain their evidence under quotation attributes with charge-prefixed labels; that is a scope limitation, not full typed charge-attribute support. Its first live request was rejected before an extraction was returned. The process was stopped during pacing before the second document. One explicitly recorded diagnostic repeated only that first request to capture the provider's otherwise-sanitized HTTP 400 error; it was not reused as extraction output or counted as a completed quotation. Together these reserved four possible HTTP-attempt slots and 28,308 estimated tokens within the candidate ceiling. Neither request reported token usage or an invoice cost.

The provider rejected the generated nullable-decimal schema's `anyOf` representation, requiring disambiguation even for the string/null primitive alternatives. This is a request-compatibility failure, not an extraction-accuracy result. The [interruption receipt](../eval/results/development/full-quotes-2026-09-22-typed-final/interrupted.json) retains the exact schema path and accounting; the original private lock, plan and usage journal remain unchanged. Earlier offline captures made zero model calls.

The second candidate changes serialization of only an exact primitive-or-null union to the equivalent nullable type array shown in Groq's documentation. It preserves decimal patterns, enums and all remaining validation; object unions are unchanged. [Zod's documented reference reuse](https://zod.dev/json-schema#reused) keeps the typed schema within the existing per-request budget. The typed request's actual contract is also included in its checkpoint identity. Independent review additionally caught a prompt-placement mistake before any typed extraction succeeded: service scope belongs in the existing item scope field, while item exclusions/specifications remain scoped attributes. That instruction is corrected and regression-tested. The model remains unchanged.

## Implemented safety and measurement changes

The default application transport remains `legacy_v5`; both new contracts require an explicit development option. The `quotation-v7` request includes its real schema in the checkpoint key, and the evaluation fingerprint includes the transport, parser, validation, prompt and scoring code. Only the source-completeness guard and safe schema-error classification also apply to the existing transport. No environment setting enables either experimental contract in the deployed application.

- A visible quantity, unit price or line amount must have a retained, source-linked value or ambiguity. A description/identifier alone no longer makes a clearly priced row complete. Swapped quantity/price cell roles are flagged even when multiplication still balances.
- Exact `Total`/`Total:` spreadsheet footers require retained subtotal/total evidence at their sole amount cell before being exempted from item-detail checks. Priced items named “Total” or “Total station” are not exempt. This regression was observed in a synthetic test during review and fixed before the partitioned run.
- The separate readiness gate requires complete application/parser status, all expected items and correct, evidence-linked critical stated fields. Its fixed denominators include rejected and unattempted documents. Known precise PDF evidence cannot pass by falling back to a page number.
- Critical non-value states are checked as well; an invented shipping price fails even when the stated-field score is perfect. Missing containers remain missing. Matching `not_stated` is an absence of assertion, not verified absence; source-linked non-value counts are separate diagnostics.
- Schema request errors are distinguished from malformed model generations. Only fixed error types, allowlisted codes and constrained schema paths can enter a report. Private provider messages and generations remain ignored. No diagnostic triggers an extra request, semantic retry, correction or accepted checkpoint.

These checks prevent particular false-completeness and evidence failures. They do not establish semantic correctness of all fields, item-versus-charge classification, unlabelled facts, arbitrary layouts or unannotated commercial terms.
