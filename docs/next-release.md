## Further engineering work

The additive Neon migration `202609200001_capacity_and_intent_expiry.sql` was applied on 20 September to the dedicated project/branch in one transaction, SHA-256 `450f22f957684221fe1a4bc455645829782b7f75e707a9302587b69dcc61dc9d`. It enforces workspace limits of 20 comparisons, 50 originals and 100 MiB of original-file reservations, plus shared project limits of 100 comparisons, 200 originals and 250 MiB. Finalization rejects unfinished intents older than 24 hours; the bounded expiry sweep queues their deletion. Failed deletion retains capacity until object cleanup succeeds after the ticket grace period. A document trigger preserves cleanup records during comparison and managed-account cascades, including accounts with parsed/item records. Six independent-session PostgreSQL checks and the embedded SQL tests passed. Scheduled use of the new expiry sweep still depends on deploying its updated worker; the migration alone does not update worker code. See [Neon capacity and expiry](../neon/README.md#pilot-capacity-and-expiry).

An on-demand private Workspace status panel now reports the buyer's reserved original-file capacity, pending cleanup, configured processing availability and queue counts. It exposes only a boolean for shared capacity, never other owners' usage, and does not continuously poll or claim to test provider health. Verify the panel on the updated deployed web application as part of its release checks.

These limits do not bound all database usage: parsed text, extraction/checkpoint data, indexes and comparison-history snapshots consume additional space. Every edit can add a full history snapshot. Do not claim unlimited history or a hard provider-size guarantee. Add bounded retention and a tested database-growth guard that still permits deletion. Until then, monitor the dedicated Free database, pause admission near its allowance, and delete unused comparisons while database writes still work; physical space/provider metrics may not shrink immediately. Recovery must preserve durable private-object cleanup and must not require a paid upgrade.

A read-only hosted backup and restoration into a new local directory passed on 20 September for the five synthetic originals: **538,486 bytes**, all hashes, **197 source spans**, comparison revision and zero pending local jobs were verified. No existing personal directory or server was changed. Continue periodic recovery drills on settled work; cloud database restoration, encrypted backups and recovery of every possible layout remain unverified. See [hosted-to-local recovery](cloud-recovery.md). An Excel export is a decision report, not a full application backup. Keep the public fixture workspace independent of cloud uptime.

The model's local minute/day counter is an extra guard, not global usage accounting. Before broader multi-user AI access, add persistent token admission shared across web and worker. Provider Free quotas remain authoritative. Preserve failed-output journals privately and avoid treating accepted schema shape as proof of correct interpretation.

## Later scope

DOCX, handwriting, broad multilingual OCR, graduated pricing, automatic bundle allocation, weighted scoring, live FX, shared teams and procurement integrations remain deferred. Expand only after permissioned examples and independent measurements establish useful support boundaries. No supplier outreach, autonomous purchase or paid service is part of this release.
